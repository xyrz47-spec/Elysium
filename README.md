# Elysium

여러 AI를 한 팀처럼 엮어 쓰는 Windows 데스크톱 AI 클라이언트입니다. Claude Code·Codex·Antigravity·OpenCode 같은 AI CLI와 Claude·OpenAI·Gemini·NVIDIA API를 한 화면에서 고르고, 섞고, 서로 검토시킵니다. 큰 작업은 여러 워커에게 나눠 동시에 맡기고, 총괄 AI가 검토·병합·커밋까지 이끕니다. 폰 앱(Elysium Remote)으로 밖에서도 PC의 작업을 보고 지시할 수 있습니다.

- 데스크톱: Tauri 2 + Rust + React/TypeScript (Windows 11)
- 폰: Tauri 2 Android 앱 `mobile/`
- 버전: 데스크톱 1.0.0, 폰 0.1.0

## 주요 기능

- **AI 자동 선택**: 요청의 종류·난이도를 보고 알맞은 AI와 노력 단계(모델·추론 강도)를 골라 토큰을 아낍니다. 첫 AI가 실패하면 다음 AI로 넘어갑니다.
- **검토와 토론**: 어려운 요청은 다른 회사의 AI가 초안을 검토하고, 정확도가 중요한 요청은 두 AI가 따로 답한 뒤 반론하고 세 번째 AI가 판정합니다.
- **병렬 작업**: 파일 작업을 하위 작업으로 나눠 최대 64개 워커가 각자의 작업 공간에서 동시에 일합니다. 총괄 AI가 명령을 검토하고, 바뀐 파일을 합치고, git 커밋을 검토합니다.
- **회사형 조직**: 팀을 본부·부서로 묶고, 팀장끼리만 짧은 보고를 주고받게 해 큰 작업에서도 토큰이 불어나지 않게 합니다.
- **세션 메모리**: 한 대화 안의 모든 AI가 같은 기억을 씁니다. 다른 AI가 한 말도 이어서 압니다.
- **스킬·플러그인**: Claude Code와 같은 형식. 기본 스킬 20여 종이 들어 있습니다.
- **폰 원격 제어**: QR로 페어링하고, 지문 고정 TLS로만 연결합니다. 다른 네트워크에서도 포트 포워딩 없이 붙습니다.
- **편의 기능**: 모든 AI에게 미리 알려 둘 말(나에 대해·답변 방식), 답변 언어·길이, 자주 쓰는 프롬프트, 대화 내용까지 찾는 세션 검색, 세션 고정·이름 바꾸기, 질문 다시 보내기·고쳐서 보내기, 작업 끝 알림, 글자 크기·대화 폭.

## 필요한 것

- Windows 11, WebView2(Windows 11에 기본 포함)
- Node.js 20 이상(이 PC: 24.21), Rust stable(이 PC: 1.99)
- AI CLI 하나 이상 또는 API 키 하나 이상([AI 연결](#ai-연결))
- 폰 앱을 빌드하려면: Android Studio(포함된 JDK), Android SDK, NDK 28.2.13676358

> 빌드 산출물 위치는 `.cargo/config.toml`(데스크톱)과 `mobile/.cargo/config.toml`(폰)의 `target-dir`에 `C:/Users/HOYA/.elysium-build/...`로 정해져 있습니다. OneDrive 같은 동기화 폴더에 수 GB의 산출물이 올라가지 않게 하려는 것입니다. 다른 PC에서는 이 경로와 `scripts/install-windows.ps1`의 `$src`를 알맞게 바꾸세요.

## 설치와 실행

```powershell
npm install
npm run tauri dev                      # 개발 실행
npx tauri build --debug --no-bundle    # 개발용 실행 파일
cd src-tauri; cargo test               # 단위 테스트(데스크톱 235개, 폰 앱 mobile/src-tauri 6개)
```

**Windows 앱으로 설치**(관리자 권한 필요 없음):

```powershell
npx tauri build --no-bundle                                           # 릴리스 빌드(콘솔 창 없음)
powershell -ExecutionPolicy Bypass -File scripts\install-windows.ps1  # %LOCALAPPDATA%\Programs\Elysium + 시작 메뉴·바탕화면 바로 가기
```

- 새로 빌드한 뒤 스크립트를 다시 실행하면 설치본을 바꿔 넣습니다. 설치된 앱은 먼저 닫아 두세요.
- 대화·설정(`%APPDATA%\com.hoya.elysium`)과 API 키는 개발용 빌드와 같이 씁니다.
- 설치 파일(.msi/.exe)로 묶으려면 `npx tauri build`를 쓰세요. 처음에 WiX·NSIS 도구를 내려받습니다.

## AI 연결

AI CLI를 설치해 로그인하거나, 설정 → API 키에 키를 넣으세요. 둘 다 써도 됩니다. 새로 설치했다면 설정 → CLI → "다시 찾기"를 누르세요.

| AI | 설치 | 확인 상태 |
| --- | --- | --- |
| Claude Code | https://claude.com/claude-code | 실제 출력으로 확인(2.1.299) |
| Codex | `npm i -g @openai/codex` | 공개된 출력 형식 기준으로 연결, 실제 실행은 미확인 |
| Antigravity | Antigravity 설치 후 `agy`로 로그인 | 실제 출력으로 확인(agy 1.4.10) |
| OpenCode | `npm i -g opencode-ai` | 실제 출력으로 확인(opencode 2.2.5), 무료 모델만 |
| Claude API · OpenAI API · Gemini API · NVIDIA API | 설정 → API 키 | NVIDIA만 실제 호출 확인, 나머지는 스트림 해석 단위 테스트만 |

- API 키는 Windows 자격 증명 관리자에만 저장합니다. 환경 변수 `ANTHROPIC_API_KEY`·`OPENAI_API_KEY`·`GEMINI_API_KEY`·`NVIDIA_API_KEY`·`TYPESAFE_API_KEY`도 읽습니다.
- API는 대화 모드에서 빠른 답과 검토에 씁니다. 작업 모드에서는 Elysium이 이 PC에서 파일·PowerShell 도구를 대신 실행해 줍니다(`api_agent.rs`).
- 모델 이름은 설정에서 바꿀 수 있습니다. 기본값은 `claude-sonnet-5-5`, `gpt-5`, `gemini-2.5-flash`, `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning`입니다.
- 거절된(401·403) API는 키를 다시 넣을 때까지 자동 선택에서 빠집니다.

## 요청 하나가 처리되는 과정

`src-tauri/src/orchestrator.rs`

1. **스킬**: `/이름`으로 부릅니다. JEV를 켜 두면 켜 둔 스킬 중 요청에 분명히 맞는 하나를 골라 지시문을 붙입니다.
2. **JEV 판단**(설정에서 켰을 때): 요청의 종류(코드·글쓰기·조사·분석·대화·번역), 난이도(0~3), 정확도 중요도(0~3)를 판단합니다. 확신이 50% 미만이거나 실패하면 규칙으로 정합니다.
3. **AI 고르기**: 입력창이 "자동"이면 종류별 순서로 고릅니다(코드: Claude Code → Codex → Antigravity → API, 대화·번역: 빠른 API 먼저, 조사: Gemini 먼저). JEV를 켜 두면 일을 해낼 수 있는 AI 중 가장 싼 쪽을 고릅니다. 직접 고를 수도 있습니다.
4. **허락**: 작업 모드에서 파일을 고치는 요청은 허락 카드를 띄우고, 허락한 뒤에만 편집 도구를 켭니다. 10분 안에 답이 없으면 취소합니다.
5. **초안**: 고른 AI가 답을 쓰고, 글자와 도구 사용이 실시간으로 보입니다.
6. **노력 단계**(JEV를 켰을 때): 난이도로 단계를 정합니다. 확신이 낮으면 각 엔진의 기본값을 씁니다.

   | 단계 | 조건 | Claude Code | 노력치(Claude Code·Codex·OpenAI·Gemini·Claude API) | API 최대 출력 |
   | --- | --- | --- | --- | --- |
   | 가볍게 | 난이도 < 1.0(대화·번역은 < 1.5), 작업 모드 제외 | `--model haiku` | low | 1,500 |
   | 보통 | 난이도 < 2.0 | `--model sonnet` | medium | 4,000 |
   | 깊게 | 그 밖 | 기본 모델 | high | 8,192 |

   NVIDIA는 노력치 대신 Nemotron의 생각 단계를 켜고 끕니다(`chat_template_kwargs.enable_thinking`, 가볍게 = 끔).
7. **검토**(설정: 자동·항상·토론·끄기): 난이도 2.0 이상이면 다른 회사의 AI가 초안을 검토해 최종 답을 씁니다. 다른 회사가 없으면 다른 엔진, 그것도 없으면 같은 엔진이 새 세션에서 검토합니다.
   - 검토자에게 초안 AI가 확인한 자료(읽은 파일·검색)를 알려 줍니다. 검토 답이 초안보다 지나치게 짧거나 '모름'만이면 버리고 초안을 씁니다.
8. **토론**: 정확도 중요도 2.0 이상, `debate: true` 스킬, 또는 설정의 "토론"이면 검토 대신 토론합니다.
   - 서로 다른 회사의 두 AI가 동시에 따로 답합니다(3분 한도).
   - 보통·깊게 단계면 서로의 답을 읽고 반론한 뒤 고친 답을 냅니다(2분 한도).
   - 판정 AI(후보 중 가장 강한 AI)가 사실·숫자·계산을 확인해 하나로 정리하고, 갈린 쟁점은 끝에 적습니다.
   - 가장 정확하지만 호출이 4~5배입니다.

답 아래 "과정"을 펼치면 단계·시간·토큰·추정 비용·검토 전 초안·각 AI의 답이 보입니다.

## 병렬 작업: 총괄과 워커

작업 모드에서 여러 에이전트를 쓰라고 하거나("에이전트 4개로", "1팀 - Sonnet x2" 같은 팀 구성), JEV가 독립적으로 나눌 수 있다고 판단하면 병렬로 돕니다.

1. **나누기**: 가장 강한 AI가 요청을 서로 겹치지 않는 하위 작업으로 나눕니다(`teamwork.rs`). 요청 글에 적은 팀 구성은 그대로 지킵니다.
2. **로드맵**: 무료 OpenCode CLI가 하위 작업마다 맡을 AI와 노력 단계를 정합니다(`roadmap.rs`). OpenCode가 없거나 답을 읽지 못하면 처음 계획을 씁니다.
3. **작업 공간**: 워커마다 작업 폴더의 사본에서 일합니다. 폴더가 너무 크면 `.gitignore`에 걸린 파일을 빼고, git 저장소면 git worktree를 씁니다(`.elysium/worktrees` 아래).
4. **총괄**(`leadrun.rs`): 워커의 명령 요청을 검토해 허용·거부하고, 창을 띄우는 실행은 창 테스트 대기열(기본 1개씩)로 보냅니다. 막힌 워커에게는 지시를 보내거나 사용자에게 묻고, 단계 중에 워커를 더하거나 뺄 수 있습니다.
5. **반영과 커밋**: 워커가 쉴 때마다 바뀐 파일을 메인 폴더에 반영합니다. 다른 워커가 먼저 고친 파일은 덮지 않고 충돌로 넘깁니다. git 저장소면 총괄이 변경을 검토해 커밋합니다(설정에서 끌 수 있음).
6. **통합**: 통합 AI가 원래 폴더에서 맞물림·충돌·실패한 부분을 마무리하고 빌드·테스트로 확인합니다. 남은 일이 크면 병렬 단계를 최대 2번 더 덧붙입니다.

**팀**: 한 하위 작업을 워커 여럿이 같은 작업 공간에서 함께 맡으면 팀이 됩니다. 팀원은 답 끝의 `elysium-group` 블록(`say`, `claim`, `done`)으로 대화합니다.
- 첫 라운드에는 팀장(팀원 1)만 역할과 파일을 나눕니다. 다른 팀원은 그 분담에서 시작합니다.
- 세션을 이어 쓰는 팀원은 아직 보지 않은 글만 받습니다. 이어 쓸 수 없는 팀원은 지난 기록을 받되 이미 본 글은 240자로 줄여 받습니다.
- 전하는 글은 3문장 이내로 쓰게 하고, 한 글은 1,200자까지만 전합니다.
- 같은 파일을 맡겠다는 팀원이 둘이면 나중 사람은 한 라운드 쉬며 정리합니다.
- 끝나면 AI를 한 번 더 부르지 않고, 팀원들의 마지막 글과 맡은 파일로 결과를 정리합니다.

## 회사처럼 일하기: 부서 · 팀 · 팀장

큰 작업은 팀을 부서로 묶어 회사처럼 돌릴 수 있습니다. 요청 글에 이렇게 씁니다.

```text
프론트엔드 본부:
- 1팀 - Claude Haiku 5.5 high x2
- 2팀 - Gemini 3.8 Flash high x2
백엔드 본부:
- 3팀 - Codex x2
```

- 이름이 본부·부서·사업부·부문·상위 그룹·division·department로 끝나는 줄(`프론트엔드 본부:`)이나 제목(`## 개발 본부`)이 부서를 엽니다. 뒤따르는 팀 줄이 그 부서에 들어갑니다.
- 부서 안의 부서는 들여 쓰거나(`  화면 부서:`) 한 줄에 `개발 본부/화면 부서`처럼 씁니다. `---` 줄은 모든 부서를 닫습니다.
- 부서를 적지 않아도 하위 작업이 6개 이상인 큰 작업이면 나누는 AI가 스스로 부서를 정할 수 있습니다. 적은 부서는 그대로 지킵니다.

**누가 누구와 이야기하는가**
- 팀마다 팀장이 있습니다. 혼자 일하는 팀은 그 워커, 여럿이 일하는 팀은 팀장(팀원 1)입니다.
- 한 부서 안에서는 그 부서에 바로 속한 팀의 팀장과 하위 부서의 부서장끼리만 보고를 주고받습니다.
- 부서장은 부서의 첫 팀 팀장입니다. 한 단계 위에서 다른 부서장, 총괄 직속 팀과 이야기합니다.
- 부서가 하나도 없으면 팀끼리는 이야기하지 않습니다(예전과 같음).

**토큰을 아끼는 규칙**
- 보고는 500자까지입니다. 팀장은 `elysium-group` 블록의 `report`에 쓰고, 없으면 팀원 글을 짧게 모읍니다. 혼자 일하는 팀장은 차례 끝 글의 끝부분을 보고로 씁니다.
- 보고는 받는 팀장이 어차피 일하는 다음 차례 앞에 붙습니다. 보고를 읽히려고 쉬는 워커를 깨우지 않으므로 차례가 늘지 않습니다.
- 한 번에 아직 받지 않은 최근 보고 6개까지만 받고, 같은 말을 되풀이한 보고는 올리지 않습니다.

총괄 패널의 작업자 현황에 조직도가 나옵니다. 부서 카드(접기, 팀 수, 워커 상태 점) 안에 하위 부서와 팀 카드가 들어가고, 부서마다 **팀장 회의** 기록이 있습니다. 보고는 답과 함께 저장됩니다.

## 편의 기능과 설정

**답변 방식**(설정 → 답변 방식)
- 답변 언어: 자동(한국어, 다른 언어로 물으면 그 언어)·한국어·English·日本語·中文.
- 답변 길이: 자동·짧게(결론부터, 코드·숫자·경고는 줄이지 않음)·자세히(배경·이유·예시·주의할 점).
- 모든 AI에게 미리 알려 둘 것: 직업, 쓰는 언어·도구, 선호하는 답 형식 같은 것을 2,000자까지 적어 둡니다. 모든 요청의 지시 끝에 붙고(초안·검토·토론·워커 모두), 이번 요청과 어긋나면 이번 요청이 우선합니다. 매번 토큰을 쓰므로 꼭 필요한 것만 적으세요.

**자주 쓰는 프롬프트**
- 입력창의 책 단추에서 골라 넣습니다. 쓰던 글이 있으면 다음 줄에 붙입니다.
- 같은 메뉴에서 "지금 입력한 글 저장"으로 바로 저장하고, 설정에서 이름과 내용을 고치거나 지웁니다. 예시 5개(코드 리뷰, 핵심 요약, 번역, 업무 메일, 오류 원인 찾기)를 한 번에 넣을 수 있습니다.

**세션 목록**
- 찾기는 제목·폴더에 더해 모든 대화 내용에서 찾고, 찾은 곳의 앞뒤 글을 카드에 보여 줍니다.
- 오른쪽 클릭 메뉴: 맨 위에 고정·고정 해제, 이름 바꾸기(F2 또는 두 번 누르기), 삭제. 고정은 이 PC에만 기억합니다.

**결과 카드**
- 다시 보내기: 같은 질문을 같은 방식(대화·작업·만들기·회의)으로 다시 보냅니다(첨부 파일은 빼고). 이 세션의 작업이 끝난 뒤에 됩니다.
- 고쳐서 보내기: 질문을 입력창에 넣어 고친 뒤 보냅니다.

**화면 · 알림**
- 글자·화면 크기(작게·보통·크게·더 크게)와 대화 폭(보통·넓게)을 고릅니다. 이 PC에만 기억하고 워커 창에도 같은 크기가 적용됩니다.
- 작업이 끝나면 알리기: 다른 창을 보고 있을 때 답이 끝나면 작업 표시줄의 Elysium 단추가 깜박입니다.

설정 창 맨 위의 바로 가기 줄로 원하는 항목에 바로 갑니다.

## 입력 토큰 줄이기

AI CLI는 도구를 쓸 때마다 그때까지의 대화 전체를 다시 읽습니다. 그래서 긴 작업은 출력보다 입력 토큰이 훨씬 많습니다(2026-11-05 이 PC의 최근 7일: 입력 6억 6,700만 · 출력 1,670만, 워커 한 번이 최대 4,867만 입력). Elysium은 이렇게 줄입니다.

- **총괄은 세션을 이어 쓰지 않습니다.** 예전에는 부를 때마다 같은 세션을 이어 써서 앞선 모든 판단을 다시 읽었고, 호출이 늘수록 입력이 제곱으로 늘었습니다. 지금은 매번 새 세션에 필요한 맥락(요청 4,000자, 워커 목록, 최근 판단 10개, 사용자와 나눈 최근 말 6개)만 보냅니다.
- **Claude Code는 대화를 일찍 요약합니다.** `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50`으로 문맥의 절반쯤에서 자동 요약하고, `BASH_MAX_OUTPUT_LENGTH=12000`으로 명령 출력이 대화에 그대로 쌓이지 않게 합니다(`engines.rs`의 `CLAUDE_TOKEN_ENV`).
- **작업 모드 지시에 출력 줄이기 규칙을 넣습니다.** 폴더 전체 재귀 나열 금지, 큰 파일은 필요한 줄만, 명령 출력은 `Select-Object -First/-Last 40`과 조용한 빌드 옵션(`orchestrator.rs`의 `LEAN_SYSTEM`).
- **Elysium이 대신 돌린 명령의 출력**은 12,000자까지만 돌려줍니다. 앞 3분의 1과 뒤 3분의 2를 남깁니다(오류는 대개 끝에 있음).
- **병렬 워커는 세션 요약만 받습니다.** 전체 요청과 자기 몫을 따로 받으므로 지난 대화 전문은 붙이지 않습니다.
- 팀 대화의 절약 규칙은 [병렬 작업](#병렬-작업-총괄과-워커)을 보세요.

## 세션 메모리

`src-tauri/src/memory.rs`

- 같은 세션(대화)에서는 모든 AI(초안·검토·토론·판정, CLI·API)가 같은 기억을 씁니다.
- 매 실행마다 세션 요약과 최근 대화 6개(누가 답했는지 포함, AI 답은 700자, 코드 블록은 줄 수만)를 요청 앞에 붙입니다.
- 자기 세션을 이어 쓰는 엔진(Claude Code `--resume` 등)에는 그 엔진이 아직 못 본 차례만 붙입니다.
- JEV를 켜 두면 요약 항목과 최근 대화 하나하나를 "지금 요청에 필요한가"로 걸러 필요한 것만 붙입니다.
- 오래된 대화는 작업이 끝난 뒤 가장 싼 AI가 1,400자 이내의 요약에 접어 넣습니다(결정·선호·사실·남은 일).
- 세션 머리의 **기억** 버튼에서 요약을 보고 지울 수 있습니다.

## 스킬 · 플러그인

형식은 Claude Code와 같습니다. 데이터 폴더(`%APPDATA%\com.hoya.elysium`)에 있고, 앱의 "스킬 · 플러그인"에서 켜고 끄고, 폴더를 열고, 새 스킬을 만들 수 있습니다.

- **스킬**: `skills/<이름>/SKILL.md`. 머리말에 `name`, `description`과 Elysium이 쓰는 `engine`(claude·codex·gemini), `review`, `debate`, `tier`(light·standard·deep), `mode`(chat·work)를 넣을 수 있습니다.
- **기본 스킬**(`src-tauri/seed-skills/`): 여러 공개 스킬에서 필요한 부분만 골라 한국어로 다시 썼습니다(출처는 각 SKILL.md 끝).
  - 핵심 절차는 `SKILL.md`, 자세한 점검표는 `references/*.md`에 둡니다. CLI는 필요한 참고 파일만 열어 읽습니다.
  - 판이 올라가면 사용자가 고치지 않은 이전 판만 새 판으로 바꿉니다. 고친 것은 그대로 두고, 지운 것은 다시 만들지 않습니다(`skills/.seeded`).
  - 개발: `ui-craft`, `perf-tune`, `root-cause`, `test-writer`, `refactor`, `security-audit`, `sql-helper`, `api-design`, `doc-writer`, `commit-message`
  - 정확도·효율: `fact-check`(토론), `token-saver`
  - 데이터: `data-analysis`, `excel-formula`
  - 업무: `email-writer`, `meeting-notes`, `business-plan`, `marketing-copy`, `presentation`
  - 학습·개인: `study-tutor`, `resume`, `travel-plan`
  - AI: `prompt-engineer`
  - 예시: `summarize`, `code-review`, `report`, `translate`
- **플러그인**: `plugins/<이름>/.claude-plugin/plugin.json` + `skills/…`(+ commands·agents 등). 켠 플러그인은 Claude Code에 `--plugin-dir`로 넘깁니다. 직접 넣은 플러그인은 꺼진 채로 시작하고, 켤 때 확인을 받습니다(훅·MCP로 명령을 실행할 수 있기 때문). 예시 플러그인 `elysium-starter`가 들어 있습니다.

## 화면

- **배경**: 창 전체에 입자 구(WebGL, 약 12,000개)가 깔립니다. AI가 일하면 소용돌이치고, 허락을 기다리면 호박색으로 바뀝니다.
- **도크**(왼쪽): 새 세션, 세션 목록(Ctrl+B), 사용량, 스킬·플러그인, 테마, 설정.
- **결과 카드**: 요청 → 릴레이 리본(JEV 판단 → 초안 AI → 검토 AI) → 결과 → 과정·복사. 답은 마크다운과 수식(KaTeX)으로 그립니다.
- **입력 캡슐**: AI 고르기, 대화/작업, 작업 폴더 칩, `/` 스킬 자동 완성, 파일 첨부.
- **오른쪽 도구**(Ctrl+J, Esc로 닫기):
  - 세션 정보: 작업 폴더, 질문 수·토큰·추정 비용·AI 시간, AI별 호출, 세션 기억.
  - 목차, 찾기(Ctrl+F), 내보내기(마크다운 복사·저장).
  - 곁질문: 대화에 영향 없이 진행 상황을 묻습니다. 대화·기억·CLI 세션에 남지 않습니다.
  - 에이전트: 실행 중인 에이전트를 보고, 멈추고, 메시지를 보냅니다.
  - 총괄 패널: 전체 진행 현황, 총괄 카드(질문·지시·직접 실행·활동 기록·커밋), 작업자 현황(조직도·팀·워커 카드), 명령 검토 기록, 창 테스트 대기열. 섹션 순서와 카드 밀도는 "패널 설정"에서 바꿉니다.
- **워커 창**(카드의 "새 창에서 열기", 다른 모니터로 옮길 수 있음):
  - 맨 위에 지금 하는 일(또는 완료·실패) 한 줄과 시간·입력/출력 토큰·비용이 보입니다.
  - 팀이면 팀원 카드(엔진·상태, 팀장 표시)를 눌러 볼 사람을 바꿉니다.
  - 탭: 작성 내용 / 사용 도구 / 담당 파일 / 팀 대화 / 팀장 보고 / 명령 검토(개수 표시).
  - 워커 출력, 실시간 로그, 팀 대화, 팀장 보고는 마크다운으로 보입니다. 글을 코드 블록 밖에서만 덩어리로 나눠, 실시간으로 글이 늘어나도 끝난 덩어리는 다시 그리지 않습니다(`LiveMarkdown.tsx`).
- **사용량**: 기간별로 엔진마다 호출 수, 입력·출력 토큰, 추정 비용, 평균 시간, 실패를 보여 줍니다. CLI 비용은 CLI가 알려 준 추정치라 구독 요금제의 실제 청구액과 다릅니다.
- **취침 모드**: PC를 쓰지 않는 동안 화면을 끄고 그리기를 멈춥니다. 작업 중에는 Windows가 절전에 들어가지 않게 하고, 창 테스트 중에는 모니터를 켜 둡니다.
- **테마**: 시스템 따라가기 → 다크 → 화이트. 강조색은 청록(`#79b8b3`) 하나입니다. 시스템의 "애니메이션 줄이기"를 켜면 움직임을 멈춥니다.

## 폰 앱 (Elysium Remote)

폰에서 PC의 세션을 보고, 질문을 보내고(PC에서 실행되고 PC 화면에도 보임), 에이전트에게 지시하고, 멈추고, 작업 모드를 허락할 수 있습니다.

**연결**
1. PC: 설정 → **폰 연결** → 원격 제어 켜기. Windows 방화벽이 물으면 **개인 네트워크**를 허용하세요.
2. 폰: `release/elysium-remote.apk`를 설치하고 **QR 찍기** → PC에서 **폰 연결하기**로 띄운 QR을 찍습니다.
3. 다른 네트워크에서는 포트 포워딩 없이 붙습니다. PC가 고정 키의 iroh 엔드포인트를 띄우고, 폰은 페어링 때 받은 공개키로 직접 연결하거나 공용 릴레이로 중계합니다(`relay.rs`, `mobile/src-tauri/src/tunnel.rs`). 릴레이는 암호화된 패킷만 봅니다. Tailscale이나 공유기 포트 포워딩(TCP 47820)도 됩니다.

**보안**
- 원격 제어는 기본으로 꺼져 있습니다. 켜면 TLS로만 받고, 폰은 QR에 담긴 SHA-256 지문과 같은 인증서만 믿습니다.
- 페어링 코드는 100비트 무작위로, 5분 동안 한 번만 쓸 수 있고 8번 틀리면 닫힙니다. 기기마다 256비트 토큰을 주고 PC에는 해시만 둡니다. 설정에서 기기를 끊으면 그 토큰은 바로 막힙니다.
- 폰의 작업 모드 허락은 설정에서 끌 수 있습니다. 원격 요청·허락·페어링은 감사 기록에 남습니다(본문은 기록하지 않음).

**폰에서 가볍게 돌게 한 것**
- 입자 배경을 약 4,000개로 줄이고, 화면 배율은 최대 1.25배, 초당 프레임은 작업 중 30·평소 20으로 낮췄습니다.
- 움직이는 배경 위의 유리 흐림(`backdrop-filter`)은 매 프레임 다시 계산되므로 폰에서는 끄고 거의 불투명한 판을 씁니다. 끝없이 칠을 다시 하는 반짝임 애니메이션도 없앴습니다.
- PC에서 오는 실시간 이벤트를 글자 조각마다 그리지 않고 0.22초마다 모아 한 번에 반영합니다(`useLiveQueue`).
- 지난 답은 다시 그리지 않고, 화면 밖 카드는 배치를 건너뛰고, 닫힌 시트 안은 그리지 않습니다.
- PC와 에이전트 상태를 6초마다 맞추고, 화면이 꺼져 있으면 건너뜁니다.

**빌드**(상위 폴더의 node_modules를 같이 씀)

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:NDK_HOME = "$env:ANDROID_HOME\ndk\28.2.13676358"
cd mobile
# CLI는 절대 경로로 부른다(Gradle이 안쪽 폴더에서 같은 명령을 다시 부르기 때문)
node "$PWD\..\node_modules\@tauri-apps\cli\tauri.js" android build --apk --target aarch64
```

- APK는 `C:\Users\HOYA\.elysium-build\android\app\outputs\apk\universal\release\`에 나옵니다. USB로 연결한 폰에는 `adb install -r <apk>`로 덮어 설치하면 페어링이 유지됩니다.
- 서명 키는 `C:\Users\HOYA\.elysium-build\keys`에 있고 저장소에 넣지 않습니다.

폰 앱이 쓰는 API: `POST /pair`, `GET /api/info|engines|conversations|approvals|usage`, `GET /api/conversations/{id}/messages`, `POST /api/send`, `POST /api/tasks/{id}/cancel`, `POST /api/approvals/{id}`, `GET /api/events`(WebSocket, PC 화면과 같은 이벤트).

## 파일 첨부

- 입력창의 클립 버튼, 끌어다 놓기, 붙여넣기(스크린샷)로 붙입니다. 메시지당 10개, 파일당 50MB입니다.
- 파일은 데이터 폴더의 `attachments` 아래에 복사되고, 세션을 지우면 함께 지워집니다.
- CLI는 파일 경로를 읽기 도구로 엽니다. API는 글 파일을 본문에 넣고 이미지(Claude는 PDF도)를 내용 블록으로 보냅니다. 첨부를 읽지 못하는 API가 먼저 답하게 되면 CLI가 먼저 답합니다.
- 에이전트는 답 안에 `[[attach: 작업 폴더 기준 경로]]` 또는 `[[file: 이름]]` 내용 `[[/file]]`로 파일을 붙입니다. 작업 폴더 안의 일반 파일만 받고 `.env`, `.pem` 같은 비밀 파일은 거릅니다. 실행 파일은 눌러도 실행하지 않고 탐색기에서 보여 줍니다.
- 폰 앱도 파일을 올릴 수 있고, 이미지와 글 파일은 펼쳐 봅니다.

## OpenCode (무료 모델만)

- 무료 모델(`opencode/` 아래의 `-free` 모델과 `big-pickle`)만 씁니다. 다른 값은 저장하지 않고 실행 직전에도 다시 거르며, 실행 중 비용이 잡히면 바로 멈춥니다.
- 대화 모드는 읽기·검색 도구만 허용하고, 하위 에이전트는 다른 모델을 쓸 수 있어 항상 막습니다.
- 요청은 OpenCode Zen으로 전송됩니다. DeepSeek V4.1 Flash Free와 GLM-5.3-Flash Free는 입력을 보관·학습하지 않고, 일부 다른 무료 모델은 입력을 보관하거나 모델 개선에 씁니다(https://opencode.ai/docs/zen, 2026-11-02 확인). JEV가 민감하다고 본 요청은 이 두 모델만 씁니다.
- 무료 사용량 한도에 걸리면 다음 AI로 넘어갑니다.

## JEV (TypeSafe Jev)

설정에서 켜고 TypeSafe 키를 넣으면 빠른 판단 모델이 여러 곳에서 돕습니다(실측 약 0.2초, 요청당 약 $0.00002). 판단에 쓰는 글이 TypeSafe로 전송됩니다.

- 요청 종류·난이도·정확도 중요도, AI와 에이전트 수 고르기, 스킬 고르기
- 세션 기억 거르기(곁질문 포함), 앞선 첨부 중 지금 필요한 파일 다시 붙이기
- 답이 부족해 보이면 더 강한 다른 회사 AI에게 검토, 검토가 초안보다 못하면 초안 쓰기
- 작업이 덜 끝났으면 한 차례 더, 일시적인 오류면 한 번 더 시도
- 바뀐 파일 중 사용자에게 건넬 결과물을 골라 답에 붙이기(최대 5개)
- 병렬 작업에서 워커가 막혔는지, 명령이 안전한지 판단(허락을 대신하지는 않음)
- 입력하는 동안 모드와 스킬 추천(설정에서 끌 수 있음)

## 안전

- 요청 본문은 CLI **표준 입력**으로만 넘깁니다(명령줄 인자·셸에 넣지 않음).
- 대화 모드의 Claude Code 도구는 `Read, Grep, Glob, WebFetch, WebSearch`뿐입니다. 작업 모드는 `Edit, Write`를 더하고 `acceptEdits`로 실행합니다. Codex는 `read-only`·`workspace-write` 샌드박스를 씁니다.
- 병렬 작업의 워커 명령은 총괄의 검토를 거칩니다. "모든 명령 자동 허용"을 켜면 경고가 보이고 언제든 해제할 수 있습니다.
- CLI는 세션의 작업 폴더에서 실행합니다. 고르지 않으면 기본 작업 폴더(`문서\Elysium`, 설정에서 변경)를 씁니다.
- Claude Code는 사용자 전역 설정(훅·플러그인·MCP)을 불러오지 않습니다(`--setting-sources project --strict-mcp-config`). 실측으로 한 요청이 약 5만 토큰에서 약 8천 토큰으로 줄었습니다.
- 답의 HTML은 실행하지 않습니다. 링크는 http·https만 기본 브라우저로 엽니다.
- API 키는 자격 증명 관리자에만 두고, 로그와 오류 메시지에서 가립니다.
