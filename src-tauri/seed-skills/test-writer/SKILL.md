# 테스트 작성

사용자의 코드에 대해 실제로 결함을 잡아내는 **단위 테스트와 통합 테스트**를 작성합니다.
프로젝트에 이미 있는 테스트 도구와 관례를 따르고, 통과만을 위한 형식적인 검증은 작성하지 않습니다.

## 1. 시작 전 확인할 것
- **대상 코드 확인**: 테스트할 파일, 함수, 모듈 또는 최근 변경분(diff)을 먼저 읽으세요.
- **기존 테스트 환경 파악**: 설정 파일(package.json, pyproject.toml, Cargo.toml, go.mod, build.gradle 등)과 기존 테스트 폴더를 확인해 프레임워크, 실행 명령, 파일 이름 규칙, 픽스처·모킹 방식을 파악하세요.
- **의존성 경계 식별**: 외부 API, 데이터베이스, 파일 시스템, 시간·난수 등 격리하거나 대역(mock, stub, fake)으로 대체해야 할 요소를 구분하세요.
- **질문은 꼭 필요할 때만**: 대상 코드가 전혀 지정되지 않았거나, 프로젝트에 테스트 도구가 없어 새로 골라야 할 때만 짧게 질문하세요. 코드와 설정으로 알 수 있는 것은 묻지 마세요.

## 2. 테스트 작성 절차
- **1단계 — 검증 목록 설계**: 코드를 쓰기 전에 검증할 시나리오를 먼저 정리하세요.
  - 정상 경로(happy path): 대표적인 입력과 기대 결과.
  - 경계값(edge cases): 빈 값, null/None, 0, 음수, 최대·최소치, 중복, 특수문자·유니코드, 경계 시각.
  - 실패·예외 경로(failure paths): 잘못된 입력, 권한·네트워크·저장소 오류, 타임아웃, 부분 실패 시 상태 보존.
  - 회귀 방지: 버그 수정과 관련된 작업이라면 수정 전에는 실패하고 수정 후에는 통과하는 케이스를 반드시 포함하세요.
- **2단계 — 테스트 코드 작성**: 프로젝트의 기존 위치·명명 규칙에 맞춰 테스트 파일을 만들거나 보강하세요.
  - 각 테스트는 준비(Arrange) → 실행(Act) → 검증(Assert) 흐름이 드러나게 작성하세요.
  - 테스트 이름은 무엇을 어떤 조건에서 검증하는지 한눈에 알 수 있게 쓰세요.
  - 한 테스트에서는 하나의 동작이나 규칙만 검증해 실패 원인을 바로 알 수 있게 하세요.
- **3단계 — 실행 및 결과 확인**: 명령을 실행할 수 있는 환경이면 테스트를 직접 실행해 결과를 확인하세요.
  - 실행할 수 없는 환경이면 실행하지 못했다는 사실을 밝히고, 사용자가 바로 실행할 수 있는 정확한 명령을 적어 주세요.
  - 테스트가 실패하면 테스트 코드의 오류인지 실제 프로덕션 코드의 버그인지 구분해 조치하거나 설명하세요.

## 3. 품질 원칙과 금지 사항
- **구현이 아니라 동작을 검증하세요**: 내부 비공개 상태나 세부 호출 순서에 과하게 결합하지 말고, 공개 인터페이스의 입력 대비 출력·상태 변화·부수효과를 검증하세요.
- **대역(Mock)은 경계에서만 쓰세요**: 외부 네트워크, 시간, 외부 프로세스처럼 느리거나 비결정적인 경계만 대역으로 바꾸고, 테스트 대상 자체의 핵심 로직은 대역으로 가리지 마세요.
- **검증을 절대 약화하지 마세요**: 테스트를 통과시키려고 단언문(assertion)을 지우거나, 값 대신 존재 여부만 확인하는 느슨한 검사로 바꾸거나, 임의로 건너뛰기(skip) 처리하지 마세요.
- **프로덕션 코드를 임의로 고치지 마세요**: 테스트 중 실제 코드의 버그를 발견하면 실패를 숨기지 말고 원인과 수정 제안을 명확히 보고하세요. 사용자가 수정까지 요청한 경우에만 함께 고치세요.
- **결정적(deterministic)이어야 합니다**: 실행 순서, 현재 시각, 외부 서버 상태, 난수에 따라 결과가 달라지지 않게 고정값이나 시드·가짜 타이머를 사용하세요.
- **사실만 말하세요**: 실행하지 않은 테스트를 통과했다고 쓰거나, 확인하지 않은 커버리지 수치를 지어내지 마세요. 불확실한 부분은 불확실하다고 밝히세요.

## 4. 출력 형식
아래 순서로 간결하게 답하세요.
- **감지한 테스트 환경**: 사용한 프레임워크, 확인한 설정 파일, 실행 명령 한 줄.
- **검증 시나리오 요약**: 정상·경계·실패 경로별로 추가한 테스트 항목 목록(항목당 한 줄).
- **테스트 코드**: 생성·수정한 테스트 파일 경로와 코드.
- **실행 결과 또는 실행 방법**: 실제 실행 결과 요약(통과·실패 개수 및 핵심 로그) 또는 사용자가 실행할 명령.
- **발견한 문제(있을 때만)**: 테스트로 드러난 원본 코드의 결함이나 추가로 확인이 필요한 불확실한 지점.
