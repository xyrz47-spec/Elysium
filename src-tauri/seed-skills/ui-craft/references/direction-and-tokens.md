# 방향 정하기와 디자인 토큰

## 1. 주제에서 출발하기
- 독특한 선택은 주제의 세계에서 나옵니다: 그 분야의 재료, 도구, 말투, 오래된 관습.
  예) 등산 기록 앱 → 등고선·지도 기호·현장 메모의 거친 느낌 / 세무 도구 → 장부·도장·정확한 숫자 정렬 / 아이용 학습 → 크고 둥근 손잡이, 놀이 같은 피드백.
- 화면을 열자마자 보이는 첫 요소(히어로)는 그 분야에서 가장 특징적인 것으로: 제목 한 줄, 실제 데이터, 움직이는 데모, 바로 해 볼 수 있는 입력 등.
  "큰 숫자 + 작은 설명 + 그라데이션 강조"는 기본값이니, 정말 맞을 때만 쓰세요.

## 2. 방향 프리셋(출발점, 그대로 쓰지 말고 주제에 맞게 조정)
| 방향 | 어울리는 곳 | 특징 |
|---|---|---|
| 정밀·밀도 | 개발 도구, 분석, 관리자 화면 | 촘촘한 간격(4px 단위), 얇은 선, 고정폭 숫자, 차분한 색 하나 |
| 따뜻함·친근 | 소비자 앱, 커뮤니티 | 넉넉한 여백, 큰 반지름, 부드러운 색, 친근한 말투 |
| 신뢰·차분 | 금융, 의료, 법률 | 낮은 채도, 분명한 위계, 과한 장식 없음, 정확한 표기 |
| 편집·읽기 | 블로그, 문서, 뉴스 | 본문 글꼴이 주인공, 넓은 행간, 좁은 줄 길이(한글 35~45자) |
| 놀이·표현 | 게임, 아이, 창작 도구 | 강한 색, 과감한 형태, 눌렀을 때 반응이 큰 모션 |
| 몰입·분위기 | 미디어, AI 도구, 쇼케이스 | 배경 전체를 쓰는 장면, 떠 있는 패널, 빛·입자 같은 한 가지 효과 |

## 3. 흔한 "생성된 디자인" 티(쓰려면 이유가 있어야 함)
- 따뜻한 크림색 바탕 + 세리프 제목 + 테라코타 강조 / 거의 검은 바탕 + 형광 초록 강조 하나
- 모든 내용을 똑같은 둥근 카드로 자르고, 반지름·그림자를 전부 같게
- 제목 위의 대문자 꼬리표, 한 단어만 색칠하거나 기울인 제목, 장식용 그라데이션
- 내용이 순서가 아닌데 붙인 01/02/03 번호, 모든 섹션의 똑같은 "아래에서 떠오르기" 등장
- 링크마다 붙인 '→', 작은 라벨에 고정폭 글꼴, 가운뎃점으로 이은 메타 정보(A · B · C)
요청이 이런 모습을 원하면 그대로 따르세요. 요청이 정하지 않은 부분에서 이런 기본값을 쓰지 마세요.

## 4. 색
- 역할로 정하세요: 바탕(bg), 표면(surface: 카드·패널), 표면2(입력칸·선택 바탕), 글자(ink), 보조 글자(muted), 흐린 글자(dim), 선(line), 강조(accent), 상태(성공·경고·위험·정보).
- 강조색은 한두 개. 상태색은 강조와 겹치지 않게 따로, 항상 아이콘·글자와 같이 씁니다.
- **다크와 라이트는 따로 조정**: 자동 반전이 아니라 같은 역할을 각 바탕에서 다시 맞춥니다.
  - 라이트: 바탕을 아주 흰색으로 두면 흰 카드가 묻힙니다. 바탕을 옅은 회색(예: L* 88~92)으로, 표면은 흰색으로 띄우세요.
  - 다크: 순수 검정 대신 아주 어두운 회색, 표면은 한 단계 밝게. 강조색은 채도를 조금 낮춰 눈부시지 않게.
- 선·그림자·흐린 글자는 바탕 색조 쪽으로 물들이면(순수 회색 대신) 화면이 한 덩어리로 보입니다.
- 대비 확인: 글자 4.5:1(큰 글자 3:1), UI 경계·아이콘 3:1. 눈대중이 아니라 계산으로.

## 5. 글꼴과 크기
- 한두 가지 글꼴. 두 가지면 분명히 달라야 합니다(예: 본문 산세리프 + 숫자·코드 고정폭).
- 역할: 표시용(제목), 본문, 숫자/코드. 한국어는 Pretendard, Noto Sans KR, SUIT 등 한글이 고른 글꼴.
- 크기 단계 예: 12 · 13 · 14 · 16 · 20 · 24 · 32 · 40. 단계 밖의 크기는 만들지 마세요.
- 한국어: 본문 행간 1.6~1.75, `word-break: keep-all`, 자간은 기본 또는 아주 약간 좁게(-0.01em), 문단 길이 짧게.
- 제목은 굵기·크기·간격으로 위계를 만들고, 대문자 라벨·과한 굵기 대신 크기 차이로.
- 숫자 비교는 `font-variant-numeric: tabular-nums`.

## 6. 간격·크기·반지름·그림자
- 간격 기준 4px(밀도 높은 화면) 또는 8px. 단계 예: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64.
- 컨트롤 높이 하나로 통일(예: 32px 또는 36px), 같은 줄의 요소는 같은 높이.
- 반지름은 위계: 바깥 > 안쪽, **안쪽 반지름 = 바깥 반지름 − 안쪽 여백**(동심원). 모든 것에 같은 반지름은 피하세요.
- 그림자 두 겹: 가까운 작은 그림자(윤곽) + 멀고 흐린 그림자(높이). 반투명 테두리와 함께.
- 높이(elevation) 단계 3개 정도: 바탕 위 표면 / 떠 있는 패널 / 모달·팝오버.

## 8. 디자인 기억 파일(.interface-design/system.md) 틀
```md
# 디자인 시스템
- 방향: (예: 정밀·밀도, 차분한 청록 하나)
- 색: bg … / surface … / ink … / accent … / 상태 …
- 글꼴: 본문 …, 숫자 …, 크기 단계 …
- 간격: 4px 기준, 단계 …  / 컨트롤 높이 32px / 반지름 8·12·20
- 컴포넌트 결정: 버튼(높이·여백·반지름), 입력칸, 카드, 표 행 높이 …
- 하지 않기로 한 것: …
```
결정은 쌓입니다. 한 번 정한 값은 패턴이 되고, 완벽하지 않아도 일관된 체계가 흩어진 완벽한 값보다 낫습니다.
