# 글·상태·폼

## 화면에 쓰는 글(UX 글쓰기)
- 글은 화면을 쓰기 쉽게 만들기 위해서만 있습니다. 장식용 문구를 넣지 마세요.
- **사용자의 말로**: 시스템 구조가 아니라 하는 일로 이름 짓기("웹훅 설정" → "알림 받기").
- **능동형, 짧게**: "저장되었습니다" 대신 "저장했습니다", "제출" 대신 일어나는 일("신청하기").
- **같은 일은 같은 이름**: 버튼이 "게시"면 알림도 "게시했습니다". 흐름 내내 같은 낱말.
- **오류는 방향을**: 무엇이 잘못됐는지, 왜, 어떻게 고치는지. 사과·모호한 표현("문제가 발생했습니다") 금지.
  - 나쁨: "오류가 발생했습니다." / 좋음: "파일이 20MB를 넘습니다. 20MB 이하로 줄여 다시 올리세요."
- **빈 화면은 초대장**: 무엇을 하면 되는지 한 줄 + 그 일을 하는 버튼.
- 존댓말 수준을 하나로 통일(예: "~하세요/~했습니다"). 느낌표·이모지는 브랜드가 원할 때만.
- 숫자·단위는 붙여 쓰지 않게 줄바꿈 방지(`&nbsp;`), 말줄임은 `…` 한 글자, 따옴표는 일관되게.

## 모든 상태를 그리기
| 상태 | 무엇을 보여 줄지 |
|---|---|
| 처음(비어 있음) | 이 화면이 무엇인지, 첫 행동 버튼, (가능하면) 예시 |
| 불러오는 중 | 최종 모양과 같은 크기의 뼈대(skeleton). 300ms 안이면 아무것도 안 보여도 됨 |
| 일부만 있음 | 있는 것은 보여 주고, 빠진 부분만 표시 |
| 오류 | 무엇이 실패했는지 + 다시 시도 버튼 + (필요하면) 자세히 |
| 성공 | 짧은 확인(알림 또는 제자리 표시), 다음 행동 |
| 권한 없음 | 왜 못 보는지, 누구에게 요청하는지 |
| 오프라인·느림 | 마지막으로 받은 내용 + 상태 표시, 다시 연결되면 자동 갱신 |
| 아주 많음 | 페이지 나누기·가상화·검색·필터, 너무 긴 글은 줄이고 펼치기 |
| 아주 긴 글·이름 | 줄바꿈(`overflow-wrap: anywhere`) 또는 말줄임 + 전체는 툴팁·상세에서 |

## 폼
- 입력칸마다 **보이는 라벨**(placeholder는 라벨이 아님). 도움말은 칸 아래 짧게.
- 필수/선택 표시를 하나의 방식으로(대부분 필수면 "선택"만 표시).
- 알맞은 `type`(email, tel, number, url), `inputmode`, `autocomplete`(이름·주소·one-time-code). 코드·이메일은 맞춤법 검사 끄기.
- **실시간 검사는 떠날 때(blur)**, 제출 때 모두 검사하고 첫 오류로 초점. 입력 중에 빨간 오류를 띄우지 않기.
- 제출 버튼을 미리 비활성화하지 말고, 눌렀을 때 무엇이 빠졌는지 알려 주기.
- 저장하지 않은 변경이 있으면 떠날 때 경고.
- 길면 단계로 나누고 진행 표시, 각 단계에서 돌아갈 수 있게.
- 비밀번호: 보기 버튼, 붙여넣기 허용, 규칙은 미리 보여 주기.
- 한국어 입력: 조합 중 Enter 무시, 이름·주소 칸은 충분히 넓게, 전화번호는 하이픈 자동.

## 확인 창과 알림
- 확인 창 제목은 질문("'보고서' 세션을 삭제할까요?"), 본문은 결과("대화와 기록이 지워지고 되돌릴 수 없습니다"), 버튼은 동작 이름("영구 삭제" / "취소").
- 알림(toast)은 3~5초, 중요한 오류는 사용자가 닫을 때까지. 알림 안에 되돌리기를 둘 수 있음.
- 같은 알림을 여러 번 쌓지 않기.
