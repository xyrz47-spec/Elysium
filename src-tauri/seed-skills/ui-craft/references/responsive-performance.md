# 반응형과 화면 성능

## 반응형
- 확인 폭: 375(휴대폰), 768(태블릿), 1024(작은 노트북), 1440(데스크톱), 1920 이상(넓은 화면).
- 휴대폰: 좌우 16px 여백, 가로 스크롤 없음, 입력 글자 16px 이상(작으면 iOS가 확대), 확대 막지 않기, 안전 영역 `env(safe-area-inset-*)`.
- 크기는 CSS가 정하게: 그리드·플렉스·`clamp()`·`minmax()`·컨테이너 쿼리. JS로 폭을 재서 배치하지 않기.
- 줄 길이: 한글 본문 35~45자, 영문 60~75자. 넓은 화면에서는 본문 폭을 제한하고 가운데로.
- 넓은 화면: 내용을 늘리기보다 여백·보조 패널을 늘리고, 화면의 중심(시선의 기준)을 정하기.
- 터치 기기: hover 의존 없애기, 누르는 영역 44px, 엄지가 닿는 아래쪽에 주요 동작.
- 불필요한 스크롤바 없애기(내용이 들어가면 overflow 숨김), 스크롤 영역은 하나씩.

## Core Web Vitals(사용자 기기 75번째 백분위 기준)
| 지표 | 좋음 | 개선 필요 | 나쁨 | 주로 고칠 곳 |
|---|---|---|---|---|
| LCP(가장 큰 내용 그리기) | ≤ 2.5초 | ≤ 4초 | > 4초 | 서버 응답, 큰 이미지 우선 불러오기, 막는 CSS·JS 줄이기, 글꼴 |
| INP(입력 반응) | ≤ 200ms | ≤ 500ms | > 500ms | 긴 JS 작업 쪼개기, 이벤트 처리 가볍게, 무거운 계산은 Worker로 |
| CLS(밀림) | ≤ 0.1 | ≤ 0.25 | > 0.25 | 이미지·광고·글꼴 자리 미리 잡기, 위에 끼워 넣지 않기 |
실험실 한 번 측정은 실제 사용자 데이터가 아닙니다. 현장 데이터로 영향을 보고, 실험실 추적으로 원인을 찾으세요.

## 예산(출발점, 제품에 맞게 조정)
- 전체 페이지 1.5MB 이하, 압축 JS 300KB 이하, CSS 100KB 이하, 첫 화면 이미지 500KB 이하, 글꼴 100KB 이하, 외부 코드 200KB 이하.

## 화면 쪽 자주 하는 처방
- 이미지: 알맞은 크기(srcset), 최신 형식(AVIF/WebP), 첫 화면 밖은 지연 불러오기, 크기 속성으로 자리 잡기, 첫 화면 큰 이미지는 우선 불러오기.
- 글꼴: 필요한 글자만(한글은 부분 집합·동적 분할), 중요한 글꼴만 미리 불러오기, `font-display: swap`.
- JS: 경로별 코드 나누기, 큰 라이브러리는 필요할 때 불러오기, 묶음(barrel) 파일 통째로 가져오지 않기, 외부 스크립트는 늦게.
- 목록: 수백 개 이상은 가상화, 화면 밖 섹션은 `content-visibility: auto`.
- 애니메이션 GIF 대신 반복 영상, 움직임은 transform/opacity.

## React에서 성능 우선순위(높은 것부터)
1. **순차 대기 없애기**: 서로 기다릴 필요 없는 요청은 동시에, 필요한 곳에서만 await, 화면을 Suspense 경계로 나누기.
2. **번들 줄이기**: 동적 import, 묶음 파일 대신 직접 경로 import, 외부 코드 늦게.
3. **서버에서**: 같은 요청 캐시·중복 제거, 클라이언트로 보내는 데이터 최소화, 응답 뒤로 미룰 수 있는 일은 미루기.
4. **클라이언트 데이터**: 같은 요청·이벤트 리스너 중복 없애기.
5. **다시 그리기 줄이기**: 계산으로 얻을 수 있는 값은 상태로 두지 않기(effect로 동기화 금지), 컴포넌트 안에서 컴포넌트를 정의하지 않기, 필요할 때만 memo.
6. **그리기**: 화면 밖 내용 건너뛰기, 바뀌지 않는 JSX는 밖으로, 느린 갱신은 transition으로.
7. **JS 미세 최적화**(뜨거운 경로에서만): 찾기는 Map/Set, 반복 합치기.
8. **고급 패턴**(상황에 따라): 한 번만 초기화, 안정적인 이벤트 핸들러 참조.
측정 없이 memo를 여기저기 붙이지 마세요. 프로파일러로 다시 그려지는 곳을 확인하고 고치세요.
