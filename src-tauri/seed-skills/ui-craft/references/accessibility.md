# 접근성 점검표(WCAG 2.2 AA 기준)

자동 검사(axe, Lighthouse)는 시작일 뿐입니다. 점수 100이어도 아래 수동 점검을 해야 합니다.

## 인식할 수 있게(Perceivable)
- [ ] 의미 있는 이미지에 대체 글(`alt`), 장식 이미지는 `alt=""` 또는 `aria-hidden`.
- [ ] 아이콘만 있는 버튼에 접근 가능한 이름(`aria-label` 또는 화면에 숨긴 글).
- [ ] 글자 대비 4.5:1, 큰 글자(24px 또는 굵은 19px 이상) 3:1, UI 경계·아이콘·초점 표시 3:1.
- [ ] 상태·오류·필수 표시를 색만으로 전하지 않음(아이콘·글자·모양을 함께).
- [ ] 200% 확대, 320px 폭에서 내용이 잘리지 않고 가로 스크롤 없이 다시 흐름(reflow).
- [ ] 줄 간격·문단 간격·자간을 사용자가 늘려도 깨지지 않음.
- [ ] 영상은 자막, 음성은 대본, 자동 재생 움직임은 멈춤 버튼.
- [ ] 제목(h1~h6)이 순서대로 위계를 이룸, 표에는 머리글(`th`).

## 조작할 수 있게(Operable)
- [ ] 모든 기능을 키보드로(Tab·Shift+Tab·Enter·Space·화살표·Esc). 키보드 함정 없음.
- [ ] 초점 표시가 항상 보이고, 고정 머리·바닥·팝업에 가려지지 않음(2.2: 초점 가림 방지).
- [ ] 초점 순서가 보이는 순서와 같음. 모달을 열면 초점이 안으로, 닫으면 연 버튼으로 돌아감.
- [ ] 누르는 영역 최소 24×24px(2.2), 모바일은 44×44px 권장. 작은 아이콘은 여백으로 영역을 키움.
- [ ] 끌기(drag)만으로 하는 동작에는 누르기 대안(2.2: 끌기 동작 대안).
- [ ] 시간 제한이 있으면 늘리거나 끌 수 있음. 1초에 3번 넘게 번쩍이는 것 없음.
- [ ] "본문으로 건너뛰기" 링크(긴 탐색이 있을 때), 페이지 제목이 내용을 설명.

## 이해할 수 있게(Understandable)
- [ ] `lang` 속성(`ko`), 브랜드·기술 이름은 `translate="no"`.
- [ ] 입력칸마다 보이는 라벨, 라벨을 누르면 그 칸으로 초점.
- [ ] 오류는 그 칸 옆에 글로, 무엇이 왜 틀렸고 어떻게 고치는지. 제출 때 첫 오류로 초점.
- [ ] 같은 기능은 화면마다 같은 이름·위치. 예상 못 한 화면 전환 없음.
- [ ] 이미 입력한 정보를 다시 묻지 않음(2.2: 중복 입력 방지). 인증에 기억력 퍼즐을 요구하지 않음(2.2: 접근 가능한 인증, 붙여넣기 허용).
- [ ] 도움말·문의 방법이 화면마다 같은 자리(2.2: 일관된 도움).

## 견고하게(Robust)
- [ ] 기본 HTML 요소 먼저(button, a, input, select, dialog, details). div에 onClick은 피함.
- [ ] ARIA는 필요할 때만, 역할·상태가 실제 동작과 맞게(`aria-expanded`, `aria-pressed`, `aria-checked`, `aria-selected`).
- [ ] 비동기 결과(저장됨, 오류, 새 메시지)를 `aria-live="polite"` 영역으로 알림.
- [ ] 접근성 트리(DevTools)에서 이름·역할이 맞는지 직접 확인.

## 한국어 화면에서 더 볼 것
- 버튼·라벨은 짧은 동사형("저장", "삭제", "다시 시도"), 화면 읽기에서 같은 이름이 여러 개면 대상을 붙임("세션 삭제").
- 날짜·숫자는 `toLocaleString("ko-KR")`, 금액 단위 표기 일관(원·$).
- 한글 입력(IME) 조합 중에는 Enter로 보내지 않게(`isComposing` 확인).

## 확인 방법
1. 마우스를 치우고 Tab으로 처음부터 끝까지.
2. 화면 읽기(Windows: NVDA·내레이터, macOS: VoiceOver, Android: TalkBack)로 주요 흐름 한 번.
3. 브라우저 200% 확대, 320px 폭, 다크·라이트, "애니메이션 줄이기" 켬.
4. 대비 계산기 또는 DevTools의 대비 표시로 글자·아이콘 확인.
