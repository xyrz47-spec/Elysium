# 디자인 리뷰와 화면 확인

## 1. 디자인 리뷰 기준(엄격하게, 심각한 순서로 적기)
| 영역 | 볼 것 |
|---|---|
| 위계 | 화면을 3초 보고 가장 중요한 것이 먼저 보이는가. 주요 동작이 하나로 분명한가 |
| 정렬·간격 | 모든 요소가 의도한 선에 맞는가(눈으로 보이는 중심은 ±1px 보정). 간격이 단계 안에 있는가 |
| 글꼴 | 크기 단계 밖의 크기, 너무 많은 굵기, 긴 줄, 좁은 행간이 없는가 |
| 색 | 토큰 밖의 색, 대비 부족, 강조색 남용, 상태색과 강조색 혼동이 없는가 |
| 표면 | 반지름·그림자·테두리의 위계가 맞는가(안쪽 반지름 ≤ 바깥), 요소와 바탕이 구분되는가(라이트 모드 특히) |
| 상태 | 올림·누름·초점·비활성·선택이 쉬는 상태보다 분명한가. 빈·불러옴·오류 상태가 있는가 |
| 모션 | 이유 있는 움직임인가, 겹치는 장식이 많지 않은가, 줄이기 설정을 지키는가 |
| 글 | 사용자의 말인가, 같은 일에 같은 이름인가, 오류가 방향을 주는가 |
| 접근성 | `accessibility.md` 점검표 |

## 2. "생성된 티" 빠르게 지우기(바꾼 부분에만)
- 이유 없는 그라데이션, 모든 카드 같은 반지름·그림자, 의미 없는 번호·대문자 꼬리표, 한 단어만 색칠한 제목, 섹션마다 같은 등장 효과, 이모지 아이콘(→ SVG 아이콘 세트), 링크 끝 '→'.
- 마지막으로 "액세서리 하나 빼기": 브리프에 기여하지 않는 장식을 하나 지우세요.

## 3. 넘기기 전 점검표(전체)
- [ ] 토큰 밖 값 없음(색·간격·반지름·글꼴 크기·그림자)
- [ ] 키보드로 끝까지, 초점 보임·가려지지 않음, 모달 초점 가둠·복귀
- [ ] 글자 4.5:1, 경계·아이콘 3:1, 색만으로 전하는 정보 없음
- [ ] 누르는 영역 24px(모바일 44px), 아이콘 버튼 이름
- [ ] 비어 있음·불러오는 중·오류·성공 상태
- [ ] 375/768/1024/1440px, 200% 확대에서 잘림·겹침·가로 스크롤 없음
- [ ] 다크·라이트에서 요소와 바탕 구분, 그림자·선이 보임
- [ ] `prefers-reduced-motion`, `transition: all` 없음, transform/opacity만
- [ ] 되돌릴 수 없는 동작에 확인/되돌리기, 저장 안 한 변경 경고
- [ ] 화면을 다시 그릴 때(필터·기간 변경) 이전 요소가 남아 쌓이지 않음(목록·반복 요소의 key가 서로 겹치지 않음)
- [ ] 콘솔 오류·경고 없음

## 4. 직접 보고 확인하기
- 가능하면 앱을 실행해 스크린샷으로 보세요. 코드만 보고 "잘 보일 것"이라고 하지 마세요.
- **살펴본 뒤 행동하기**: 동적인 화면은 불러오기가 끝날 때까지(네트워크 조용해질 때까지) 기다린 다음 DOM·스크린샷을 보고, 실제로 그려진 요소에서 선택자를 찾으세요.
- 선택자는 역할·글자·id처럼 의미 있는 것으로(`role=button[name=…]`, `text=…`).
- Playwright 예(파이썬):
```python
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b = p.chromium.launch(headless=True)
    pg = b.new_page(viewport={"width": 375, "height": 812})
    pg.goto("http://localhost:5173"); pg.wait_for_load_state("networkidle")
    pg.screenshot(path="m.png", full_page=True)
    pg.emulate_media(color_scheme="light"); pg.screenshot(path="m-light.png")
    b.close()
```
- 반복 확인: 같은 동작(예: 탭·기간 바꾸기)을 여러 번 해서 요소 수가 늘지 않는지 세어 보세요.
- 확인하지 못한 것(실기기, 화면 읽기, 특정 브라우저)은 결과에 그대로 적으세요.
