# 기술 문서 작성

이 스킬은 실제 프로젝트 파일과 설정을 직접 읽어 README, 설치 안내, API 명세, 아키텍처 노트를 작성하거나 갱신합니다.
목표는 추측 없는 정확함과 작업 중심의 간결함입니다. 독자가 문서를 보고 바로 설치·실행·수정할 수 있게 쓰세요.

## 1. 시작 전 확인할 것
- 작성할 문서 종류(README, 설치·실행 안내, API 명세, 구조 노트)와 대상 파일 경로를 먼저 확인하세요.
- 프로젝트 루트의 매니페스트·설정 파일(package.json, pyproject.toml, Cargo.toml, go.mod, Makefile, .env.example 등)과 기존 문서를 먼저 읽으세요.
- 기존 문서가 있으면 전체를 임의로 갈아엎지 말고, 기존 구조와 용어를 유지하면서 달라진 내용만 정확히 갱신하세요.
- 소스 코드나 설정 파일을 읽어 알 수 있는 사실은 사용자에게 묻지 마세요.
- 대상 독자, 외부 배포 방식, 비공개 운영 정보처럼 파일에 전혀 없고 문서 구성을 좌우하는 사항만 1~2개 이내로 질문하세요.

## 2. 작성 및 갱신 절차
- **실제 근거 확인**: 진입점 파일, 라우터·공개 함수 시그니처, CLI 옵션, 환경 변수 읽는 코드, 실행 스크립트를 직접 열람하세요.
- **명령·경로 검증**: 문서에 적을 파일 경로, 스크립트 이름, 명령어 플래그, 포트 번호가 실제 파일과 일치하는지 확인하세요.
- **작업 순서대로 배치**: 독자가 필요한 행동을 바로 할 수 있도록 "개요 → 설치·실행 → 사용법·예시 → 구조·설정 → 주의사항" 순으로 구성하세요.
- **문서 유형별 필수 항목**:
  - **README**: 프로젝트 한 줄 정의, 핵심 기능 요약, 필수 요구사항, 설치·실행 명령, 최소 사용 예시 1개, 주요 디렉터리 안내.
  - **설치·환경 안내**: 런타임·도구 버전, 의존성 설치 순서, 환경 변수 목록(이름·필수 여부·기본값·용도), 정상 동작 확인 방법, 흔한 오류 해결.
  - **API·인터페이스 문서**: 엔드포인트 또는 함수 시그니처, 요청·인자 형식과 타입, 응답·반환값 구조, 오류 상태, 호출 예시 1개.
  - **아키텍처·구조 노트**: 모듈별 책임, 핵심 데이터·호출 흐름, 상태·저장소 위치, 수정 시 지켜야 할 경계와 제약사항.
- **최종 대조**: 작성을 마친 뒤 문서 안의 모든 경로, 명령어, 환경 변수, 심볼 이름이 실제 코드와 어긋나지 않는지 다시 점검하세요.

## 3. 품질 기준과 금지 사항
- 머리말이나 홍보성 수식어 없이 핵심부터 짧고 명확하게 쓰세요.
- 긴 줄글 설명보다 바로 복사해 실행할 수 있는 정확한 명령어와 짧은 예시 1개를 우선하세요.
- 목록과 표를 활용해 한눈에 읽히게 정리하고, 한 문단에는 하나의 주제만 담으세요.
- 코드를 그대로 옮겨 적지 말고, 진입점·사용 방법·입출력 계약·주의할 제약처럼 문서를 읽는 사람에게 필요한 정보를 적으세요.
- **절대 하지 말아야 할 것**:
  - 프로젝트에 없는 스크립트, 명령어 옵션, 환경 변수, API 경로, 기본값, 요구 버전을 추측해 적지 마세요.
  - 측정하거나 확인하지 않은 성능 수치, 벤치마크, 외부 출처, 라이선스를 지어내지 마세요.
  - 실제 디렉터리와 다른 가상의 파일 트리를 예시로 적지 마세요.
  - 내용 없는 빈 제목("추후 작성", "TODO")만 남겨 문서를 부풀리지 마세요.
- 코드와 설정 파일만으로 확인할 수 없는 값(운영 서버 주소, 외부 키 발급 절차, 미구현 동작 등)은 추측하지 말고 [확인 필요: 사유]로 분명히 남기세요.

## 4. 출력 형식
- 파일 생성·수정을 수행한 경우 문서를 직접 반영한 뒤 아래 보고 형식으로 요약하고, 초안 제시만 요청받은 경우 문서 본문을 바로 출력하세요.
- **문서 기본 템플릿(새 문서 작성 시 필요한 항목만 선택)**:
  - **제목 및 요약**: 프로젝트·기능 이름과 역할을 한두 문장으로 설명합니다.
  - **요구사항 및 설치**: 필요한 런타임·패키지 버전과 설치 명령을 실행 순서대로 적습니다.
  - **실행 및 빠른 시작**: 가장 기본이 되는 실행 명령과 최소 사용 예시 1개를 제시합니다.
  - **설정 및 인터페이스**: 주요 환경 변수, 명령 옵션, API 또는 모듈 사용법을 표나 짧은 목록으로 정리합니다.
  - **프로젝트 구조**: 핵심 디렉터리와 주요 파일 경로를 실제 트리에 맞춰 한 줄씩 설명합니다.
  - **주의사항 및 문제 해결**: 자주 겪는 오류, 제약사항, 미확인 항목([확인 필요])을 적습니다.
- **작업 완료 보고 형식**:
  - **반영한 문서**: 생성·갱신한 파일 경로와 변경 요약(3~5줄 이내).
  - **확인한 근거**: 문서 작성에 참고한 실제 소스·설정 파일 경로와 검증한 명령어.
  - **확인 필요 항목**: 코드에서 알 수 없어 [확인 필요]로 표시한 사항(없으면 생략).
